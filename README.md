# House Price Predictor

> Machine learning web app that predicts house prices from property features — with a Pakistan-style sample dataset.

Enter a property's city (Lahore, Karachi, Islamabad, or Rawalpindi), area in
marla or sq ft, bedrooms, bathrooms, property age, and location tier, and the
app returns an estimated price in PKR, a typical price range, a model-computed
explanation of which inputs pushed the price up or down, and a "what-if"
(+1 bedroom) effect — all computed from the trained model, not hardcoded.

## Features

- **Price prediction in PKR** — full amount plus a compact form (crore / lakh).
- **Uncertainty band** — the price range uses the model's real test-set MAE.
- **Feature-impact explanation** — each input is re-predicted against a
  typical reference house from the sample data, so you can see what moved
  the estimate and by how much.
- **What-if analysis** — the +1 bedroom effect, computed from the model.
- **Price comparison by city** — average prices per city, computed live
  from the sample dataset.
- **Input validation** — invalid cities, tiers, or out-of-range values
  return a clear `400` error instead of a guess.
- **No API keys, no build step, works offline** — plain Flask + HTML/CSS/JS.

## Tech stack

- Python 3.10+, Flask
- scikit-learn (RandomForest regressor inside a Pipeline with one-hot encoding)
- pandas, joblib
- Vanilla HTML / CSS / JavaScript frontend

## Model performance (sample data only)

Trained on 160 houses, evaluated on a held-out set of 40 houses
(`train_test_split`, `test_size=0.2`, `random_state=42`):

| Metric | Value |
| --- | --- |
| R² (held-out) | **0.8842** |
| Mean Absolute Error (held-out) | **PKR 4,247,931** |

These numbers describe the model on this small synthetic dataset only.
Re-run `train_model.py` to reproduce them; they will change if the data changes.

## Setup

### Windows (PowerShell + VS Code)

```powershell
cd house-price-predictor
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python train_model.py
python app.py
```

Then open http://127.0.0.1:5000 in your browser.

### Linux / macOS

```bash
cd house-price-predictor
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python train_model.py
python app.py
```

Then open http://127.0.0.1:5000 in your browser.

> `train_model.py` must be run once before `app.py`, because it creates
> `model.pkl`. A copy of `model.pkl` is included in some distributions for
> convenience, but it is gitignored — cloning the repo fresh requires
> training first.

## API

### `POST /predict`

Request (JSON):

```json
{
  "city": "Lahore",
  "area": 10,
  "area_unit": "marla",
  "bedrooms": 4,
  "bathrooms": 3,
  "age_years": 5,
  "location_tier": "Standard"
}
```

Response: estimated price, price range, per-feature impacts, the +1 bedroom
what-if, model metrics, and a disclaimer. Invalid input returns
`{"success": false, "error": "..."}` with HTTP 400.

### `GET /api/city-averages`

Average sample price and sample count per city.

## Limitations — please read

- **The dataset is sample / synthetic** (`data/sample_houses.csv`, 200 rows,
  generated from plausible per-sq-ft rates, tier multipliers, and age
  depreciation plus noise). It is labelled as such throughout the code, UI,
  and this README.
- **Predictions are NOT real market prices and NOT a valuation service.**
  Do not use them to price, buy, or sell a real property.
- A 200-row synthetic sample cannot capture real neighbourhoods, amenities,
  construction quality, or market conditions.
- The MAE band is a rough uncertainty indicator, not a guaranteed range.
